## Restricted relay configuration and evidence

Review `tests/treasury/local-fork.integration.mjs` as the executable wiring example:
`RestrictedRelayer` + `RpcIO` + `FileJournal`. Production HTTP/session/DB adapters
remain blocked on H decisions. No server starts and no secret loading occurs here.

Only operator-reviewed manifests enter the service constructor; each manifest binds
ventureId, safe, guard, registry, singleton and exact runtime code hashes for all four.
Token config binds address, proxy and implementation hashes, implementation address,
decimals and EIP-712 domain. RpcIO rechecks all at a fresh pinned block before relay.
Use real sender for simulation and submission. Supply an external isolated relayer signer
through `send`; no founder signer is accepted or loaded by this code.

Set explicit max gas/price, per-minute rates, daily WBT reservation, low balance metric
handler and conservative L1-fee reserve. **OP L1 data fees are not capped by EVM gasLimit.**
The fixed L1 reservation is an operational bound, not a protocol-enforced maximum.
H must accept a measured fee policy/monitoring and restrict gas-wallet funding before
live use; do not claim a mathematical total-fee cap. Provider, alerts and secure signer
wiring are not provisioned. Use one journal per relayer wallet on one host; horizontally
scaled deployment requires H's transactional DB adapter. Crash locks/UNKNOWN entries
require reconciliation by transaction sender/nonce before operator recovery. Any unresolved
RESERVED/UNKNOWN/SUBMITTED entry blocks all new intents for that wallet. Never
remove a lock or replay an UNKNOWN entry blindly. Reservations are not refunded.

Funding domain: Tether USD / 1 / 1874 / token proxy, raw bigint amounts with 6 decimals.
Only `transferWithAuthorization(...,bytes)` is constructed. `receiveWithAuthorization`
is intentionally excluded. Payments construct token.transfer via Safe execTransaction,
all value/refund/gas fields zero, two distinct current EOA owner signatures sorted.

SUBMITTED is pending. EXECUTED requires a successful receipt with 2 confirmations,
matching token Transfer, matching Safe ExecutionSuccess for payments, independent
recipient balance read at receipt block and reverified Safe state. Store receipt hashes
and chain provenance through H's approved adapter; signature payloads stay private.
