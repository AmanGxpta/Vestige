# CR-X-002 — exact X/C2 treasury payload (refines CR-C2-009)

Status: PROPOSED, requires H acceptance. Interface specification is
`contracts/interfaces/treasury-readback-v1.d.ts` in this commit/report. This is a
contract decision only, not funding/signing/deployment authorization. Existing v0
routes remain unchanged until accepted. No approval of CR-ID-05 is implied.

FROM: flat GET treasury response, creation `typedData`, minimal payment rows.
TO: the exact nested TreasuryReadV1 / PaymentCreatedV1 shapes in the specification.
Canonical EIP-712 field name is **safeTypedData**, in creation and reload; no legacy
`typedData` alias. No deployed consumer migration is required (treasury is not live).

## Exact behavior

- Same route URLs, authentication, request bodies and error envelope. All mutation
  retries, including payment approval, carry Idempotency-Key per approved v0.
- GET returns schemaVersion:1, ventureId, verificationStatus, treasury, balanceRaw,
  tokenDecimals, depositsStatus, deposits, payments, evidence, manifest, provenance,
  operations and source. No flat Safe-address/owner aliases.
- treasury is null unless manifest and independent on-chain invariant/provenance
  checks succeed. On failure verificationStatus is UNKNOWN/UNVERIFIED, balanceRaw
  and tokenDecimals are null, depositsStatus UNKNOWN, payments empty. Unknown is
  never coerced into zero or ACTIVE.
- Balance is a raw decimal string at the stated block/hash. Token decimals are 6
  only after the checked token read. Transfer logs start at Safe deploymentBlock,
  use <=10000-block windows, and become deposit records only after successful receipt,
  exact token/to/log binding, canonical block hash and >=2 confirmations. A bounded
  incremental scan may return depositsStatus PENDING; partial history is not complete.
- GET is public for chain facts. Current verified founders get reloadable payment
  projections only when the request contains their bearer token. Non-founders get
  payments:[]; no reason, typed data or raw approval signature is exposed publicly.
- Payment projection contains original Safe hash/nonce, token, raw amount, recipient,
  reason, valid signerWallets, lifecycle, nullable relay and executedTxHash. Fresh
  pending proposals have exact stored safeTypedData. Stale nonces invalidate approvals;
  terminal proposals have safeTypedData:null. Raw signature bytes are never returned.
- Evidence is empty until an actual failed on-chain Safe transaction has >=2
  confirmations, canonical receipt/tx binding and a MINED_TRACE proving GS020.
  Simulated rejection/eth_call/one-signature API refusal never creates this record.
  Readback rechecks stored evidence's canonical receipt. No GS020 send is authorized.
- uint/block fields use decimal strings; API times are ISO UTC. Source qualifier
  TESTED_IN_SIMULATOR remains separate from labels; no two-real-humans claim.
